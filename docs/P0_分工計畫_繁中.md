## 共同原則

- Sheng 與 Sam 可以平行開始，不需要等待對方程式完成。
- backend 是 request state、A0 policy、路徑驗證與持久化資料的唯一真實來源。
- frontend 可先使用 fixture 實作與測試，integration 時才替換為真實 API。
- 不自動重試 model request；只有 backend 明確允許時才顯示手動 retry。
- 不可把 OpenAI key 放在瀏覽器端。
- 在 NASA WMTS／wire／DEM 對準驗證完成前，不可把 computed route geometry 畫在 NASA basemap 上。
- 不可宣稱 route safe、validated、recommended 或 optimal。

## Sam 的工作

1. **Request recovery API**
   - 驗證並維護 plan status endpoint：`GET /api/v1/routes/requests/{request_id}`。
   - 驗證並維護 chat status endpoint：`GET /api/v1/routes/{route_id}/chat/attempts/{request_id}`。
   - 回傳穩定欄位：`request_id`、`state`、`attempt`、`retry_allowed`、`retry_after_seconds`、`error`、`updated_at`。

2. **Idempotency 與 persistence**
   - 同一 key 不可重複啟動工作。
   - 成功 request 可以重播原 response。
   - failed／unknown request 在 backend restart 後仍可查詢。
   - retry 僅能在 backend 明確允許、且 attempt version 正確時執行。

3. **Advanced A0 context**
   - 在既有 chat request 增加 optional `advanced_context`。
   - 驗證 route objective、required waypoints、analysis focus、allow revision。
   - 驗證 advanced context 必須與已持久化的 parent route 一致。
   - free-text requirement 使用既有 bounded `message`；不可新增未受限的自由欄位。
   - `allow_supported_revision: false` 時只能解釋，不可產生 route revision。

4. **安全錯誤與 runtime status**
   - 所有預期錯誤回傳既有 JSON error envelope。
   - 不回傳 traceback、檔案路徑或 secret。
   - `ready` 與 `a0/status` 清楚區分 dataset、storage、credential 與 provider 狀態。

5. **提供 Sheng fixtures**
   - plan：running、succeeded、retryable failed、non-retryable failed、unknown。
   - chat：retryable failed、succeeded revision。
   - 每個 fixture 固定欄位、nullability 與 error shape。

## P0 完成條件

使用者可以分辨目前模式，安全送出一次 request，理解其 durable state，僅在允許時手動 retry，並在失敗後保留原成功 route。Advanced mode 能以必經 waypoint 與 bounded requirements 向 A0 請求解釋或支援的 revision。P0 不包含 route safety certification 或 NASA basemap registration。
